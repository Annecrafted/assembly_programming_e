# README - 05.asm

```asm
mov rax, 0x1122334455667788
mov rbx, 0x1234
```

loads the values `0x1122334455667788` and `0x1234` into `RAX` and `RBX` respectively. These instructions do not use the stack, so `RSP` does not change.

```asm
push rax
```

pushes the value stored in `RAX` onto the stack. During testing in GDB, I observed that `RSP` decreased by 8 bytes.

```asm
push rbx
```

pushes the value stored in `RBX` onto the stack. `RSP` decreased by another 8 bytes.

At this point, the stack contained:

```text
Top
0x1234
0x1122334455667788
Bottom
```

```asm
nop
```

does not perform any operation and does not affect the stack or register values.

```asm
pop rbx
```

removes the value `0x1234` from the top of the stack and stores it in `RBX`. `RSP` increases by 8 bytes.

```asm
pop rax
```

removes the value `0x1122334455667788` from the stack and stores it in `RAX`. `RSP` increases by another 8 bytes and returns to its original value.

## Observations

- `push rax` decreased `RSP` by 8 bytes.
- `push rbx` decreased `RSP` by another 8 bytes.
- `pop rbx` increased `RSP` by 8 bytes.
- `pop rax` increased `RSP` by another 8 bytes.
- The last value pushed onto the stack (`0x1234`) was the first value removed.
- The stack follows the Last In First Out (LIFO) principle.
- After both `POP` instructions executed, `RSP` returned to its original value.
- The stack was used to temporarily store the values held in `RAX` and `RBX`.
