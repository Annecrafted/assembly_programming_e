# README - 01.asm

```asm
mov rax, 100
mov rbx, 200
```

loads the values 100 and 200 into `RAX` and `RBX` respectively. These instructions do not use the stack, so `RSP` does not change.

```asm
push rax
```

pushes the value 100 onto the stack. While testing in GDB, `RSP` changed from `0x7fffffffd9b0` to `0x7fffffffd9a8`, a decrease of 8 bytes.

```asm
push rbx
```

pushes the value 200 onto the stack. `RSP` changed from `0x7fffffffd9a8` to `0x7fffffffd9a0`, decreasing by another 8 bytes.

At this point, the stack contained:

```text
Top
200
100
Bottom
```

```asm
pop rcx
```

removes the value 200 from the top of the stack and stores it in `RCX`. During testing, `RSP` changed from `0x7fffffffd9a0` to `0x7fffffffd9a8`, an increase of 8 bytes.

```asm
pop rdx
```

removes the value 100 from the stack and stores it in `RDX`. `RSP` changed from `0x7fffffffd9a8` to `0x7fffffffd9b0`, increasing by another 8 bytes and returning to its original value.

```asm
nop
```

does not perform any operation and does not affect the stack or register values.

## Observations

- `push rax` changed `RSP` from `0x7fffffffd9b0` to `0x7fffffffd9a8`.
- `push rbx` changed `RSP` from `0x7fffffffd9a8` to `0x7fffffffd9a0`.
- `pop rcx` changed `RSP` from `0x7fffffffd9a0` to `0x7fffffffd9a8`.
- `pop rdx` changed `RSP` from `0x7fffffffd9a8` to `0x7fffffffd9b0`.
- The last value pushed onto the stack (200) was the first value removed.
- The stack follows the Last In First Out (LIFO) principle.
- After both `POP` instructions executed, `RSP` returned to its original value.
