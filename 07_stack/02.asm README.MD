# README - 02.asm

```asm
call work
```

calls the `work` function. While testing in GDB, I observed that `RSP` changed from `0x7fffffffd9b0` to `0x7fffffffd9a8`, a decrease of 8 bytes. This happened because the return address was pushed onto the stack before execution moved to the function.

```asm
push rbp
```

pushes the current value of `RBP` onto the stack. During testing, `RSP` changed from `0x7fffffffd9a8` to `0x7fffffffd9a0`, decreasing by another 8 bytes.

```asm
mov rbp, rsp
```

sets up a new stack frame by making `RBP` point to the current top of the stack. This instruction does not change `RSP`.

```asm
sub rsp, 16
```

allocates 16 bytes of space on the stack for local variables. I observed that `RSP` changed from `0x7fffffffd9a0` to `0x7fffffffd990`.

```asm
mov qword [rbp - 8], 100
mov qword [rbp - 16], 200
```

store the values 100 and 200 in the stack frame. These instructions use the space that was allocated on the stack but do not change `RSP`.

While inspecting the stack in GDB, I observed that the value 100 was stored at `[rbp-8]` and the value 200 was stored at `[rbp-16]`.

```asm
mov rax, [rbp - 8]
mov rbx, [rbp - 16]
```

load the values back into `RAX` and `RBX`. The stack contents remain unchanged.

```asm
nop
```

does not perform any operation and does not affect the stack or register values.

```asm
mov rsp, rbp
```

restores `RSP` to the start of the stack frame and releases the space that was allocated for the local variables.

```asm
pop rbp
```

removes the saved value of `RBP` from the stack and restores it. `RSP` increases by 8 bytes.

```asm
ret
```

removes the return address from the stack and returns execution to `_start`. `RSP` increases by another 8 bytes and returns to the same value it had before `call work` was executed.

## Observations

- `call work` changed `RSP` from `0x7fffffffd9b0` to `0x7fffffffd9a8`.
- `push rbp` changed `RSP` from `0x7fffffffd9a8` to `0x7fffffffd9a0`.
- `sub rsp, 16` changed `RSP` from `0x7fffffffd9a0` to `0x7fffffffd990`.
- The values 100 and 200 were stored in stack memory at `[rbp-8]` and `[rbp-16]`.
- `mov rsp, rbp` released the local variable space that had been allocated.
- `pop rbp` restored the previous value of `RBP`.
- `ret` removed the return address from the stack and returned execution to `_start`.
- After the function finished, the stack was restored to its original state.
