# Addition Operations and EFLAGS Analysis

This directory analyzes the `ADD` and `ADC` instructions and their effect on the EFLAGS register.

---

## Program 1: `add1.asm`

- **Result:** `AL = 0x82`
- **EFLAGS:** `[ PF AF SF IF OF ]`

### Flag Analysis

- **SF (Set):** The result is negative in signed representation.
- **OF (Set):** Signed overflow occurred because adding two positive values produced a negative result.
- **PF (Set):** The result contains an even number of 1 bits.
- **ZF (Cleared):** The result is not zero.
- **CF (Cleared):** No unsigned carry was generated.

---

## Program 2: `add2.asm` (`add16.asm`)

- **Result:** `AX = 0x7EF4` (`32500`)
- **EFLAGS:** `[ IF ]`

### Flag Analysis

- **ZF (Cleared):** The result is not zero.
- **SF (Cleared):** The result is positive.
- **CF (Cleared):** No carry occurred because the result fits within the 16-bit unsigned range.
- **OF (Cleared):** No signed overflow occurred because the result fits within the 16-bit signed range.
- **PF (Cleared):** The lower byte contains an odd number of 1 bits.

---

## Program 3: `add3.asm` (Add with Carry)

- **Result:** `AX = 0x0001`
- **EFLAGS:** `[ IF ]`

### Flag Analysis

- The first addition generated a carry (`0xFFFF + 1`), setting the Carry Flag.
- `ADC` used that carry in the next addition, producing a result of `1`.
- **ZF (Cleared):** The result is not zero.
- **SF (Cleared):** The result is positive.
- **CF (Cleared):** No carry was generated by the final addition.
- **OF (Cleared):** No signed overflow occurred.
- **PF (Cleared):** The result contains an odd number of 1 bits.
